# 공공데이터·Pind 우선 장소 탐색

2026-09-27 사용자 결정. 기존 Google 우선 결정(D-030)을 대체한다.

## 동작과 비용 경계

- 기본 지도 이동·검색·공공/Pind 상세는 Supabase의 장소 카탈로그만 조회한다. 결과 없음이나 서버 오류를 Google 자동 호출로 바꾸지 않는다.
- Google 검색은 사용자가 ‘Google에서 추가 검색’을 선택한 경우에만 실행한다. 검색/ID 확정 단계에서는 사진을 요청하지 않고, 선택한 Google 상세에서만 사진 최대 1장을 요청한다.
- 사진 없는 가게는 기본 PIN을 사용한다. 자체 사진·설명·공개 게시물 데이터가 있으면 우선 표시하고, 없는 시간/평가는 미확인으로 남긴다.
- 이름이 같다는 이유로 공공 장소와 Google 후보를 자동 병합하지 않는다. 기존 내부 장소 ID와 저장/게시물 참조는 유지하고 공급자별 후보는 구분한다.
- Google 호출마다 사용자/서비스 전체의 일별 카운터를 원자적으로 검사한다. 설정/카운터 장애 시 Google 호출을 중단한다. 카운터는 호출량 제한이며 정확한 달러 예산 시스템은 아니다.

## 데이터

- 1차 공급자는 소상공인시장진흥공단 상가(상권) CSV: 상가업소번호, 이름, 업종, 주소, WGS84 좌표. 음식 관련 업종만 수입한다. 원본 URL·기준일·수입 시각을 기록한다.
- 수입은 관리자 작업이다. UTF-8 CSV를 검증한 후 사업장 고유번호로 upsert하며 내부 ID/자체 사진/게시물/저장은 보존한다. 누락된 행을 자동 삭제하거나 폐업으로 판정하지 않는다.
- `places`의 자체 장소는 사진/소개가 없어도 저장 가능하게 한다. Google 참조 전용 행의 콘텐츠 저장 금지는 유지한다. 데모·미공개·Google 참조 행은 기본 카탈로그에서 제외한다.
- 공개 Pind 게시물만 사진·리뷰 수 보완에 사용한다. RLS와 명시적인 `is_public` 조건을 함께 적용한다. 리뷰 수가 Google인지 Pind인지 UI에서 구분한다.
- 기본 검색에 공간 인덱스와 문자열 검색 인덱스를 사용하고, 최대 반경/응답 개수를 제한한다. 일반 사용자는 카탈로그를 읽기만 하며 수입·수정 권한은 관리 역할에만 준다.

## 기존 프로젝트 변경

- Flutter `PlaceRepository`/`Place`에 공공/Pind 공급자를 추가한다. 기본 요청은 새 `places` 함수, 명시적 Google 요청만 `google-places` 함수로 보낸다. 구 서버로 자동 fallback하지 않는다.
- 지도 PIN·상세·저장은 공공/Pind 내부 ID도 지원한다. 기존 유리 상세/내비게이션/친구·취향 계산은 유지한다.
- `places` Edge Function은 인증된 사용자로 DB 조회 RPC를 호출하며 서비스 키로 공개 범위를 우회하지 않는다.
- 기존 Google 함수의 자동 nearby/일괄 상세/자동 타 공급자 fallback은 차단한다. 명시적 검색·선택 상세만 허용하고 사진 요청 수를 줄인다.
- 수입 도구, SQL RLS/ID 보존/조회 테스트, API 호출 분기 테스트, Flutter 기본 탐색에서 Google 호출 0건 테스트를 추가한다.

## 적용·검증 구분

로컬 구현/테스트, 실제 원본 수입, 원격 migration/함수 배포, 일반 앱 검증을 별도로 기록한다. 원격 접근이나 원본 확보가 막히면 데모 데이터로 대신한 채 운영 연결 완료라고 보고하지 않는다. 앱 ID는 별도 요청에 따라 iOS/Android 모두 `com.pind.app`으로 통일했다. iOS 시뮬레이터에서 지도 배경 표시를 확인했다.

## 초기 데이터와 실행

2026-06-30 원본에서 음식점 업종(I2)을 Pind 원격 DB에 수입했다. 서울 141,126건, 경북 포항시 남구 5,079건·북구 5,096건이다. 원격 `public.places`의 공공 장소 합계는 151,301건, DB 크기는 142 MB다. 나머지 지역은 수입하지 않았으며 전국 커버리지를 주장하지 않는다.

원본은 소상공인시장진흥공단의 [상가(상권)정보_20260630](https://www.data.go.kr/data/15083033/fileData.do) 파일이다. 상가업소번호, 상호명/지점명, 업종 소분류, 도로명주소(없으면 지번주소), 위도/경도, 원본 기준일만 앱 장소 정보로 사용한다. 사진·소개·영업시간·리뷰·실시간 영업 상태는 원본에 없어 생성하지 않는다. 원본은 무료이며 이용허락범위 제한 없음으로 표시된다. 등록된 장소가 최신 시점에도 영업 중인지는 별도 검증이 필요하다.

```sh
# 원본 ZIP은 저장소에 포함하지 않는다.
node scripts/import_sbiz.mjs --zip artifacts/public-data/sbiz-20260630.zip --entry 서울 --region 서울특별시 --date 2026-06-30
node scripts/import_sbiz.mjs --zip artifacts/public-data/sbiz-20260630.zip --entry 경북 --region 경상북도 --city 포항시 --date 2026-06-30
# 원격 반영 시 --apply --project-ref <검증한 프로젝트 참조 ID>를 추가한다.
```

서버 설정은 `supabase/functions/.env.example`을 따른다. 기본 호출 제한은 사용자 20회/일, 프로젝트 전체 1,000회/일이며 각 검색·resolve·상세·사진 요청을 별도로 센다. 인증된 익명 계정도 전체 한도를 공유한다. 한도 테이블 오류 시 Google 요청을 보내지 않는다. 실제 금액 상한/비용 예측을 보장하지 않는다.

원격 migration 이력을 가져와 로컬 초기 파일명의 차이를 조정했다. 기존 로컬 변형은 `doc/archive/migration-variants/`에 보존했다. `db push --dry-run`에서 신규 두 migration만 확인한 후 적용했고 `places`와 `google-places`를 함께 배포했다. 향후 다른 지역 수입 전에 데이터 범위와 저장 공간을 검토한다.
