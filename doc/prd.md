# Pind PRD v3 — Flutter / Supabase

수정일: 2026-09-26. 최신 [Figma 개발용 페이지](https://www.figma.com/design/AepN5S4XiejtlWS52Q7Arg/Pind?node-id=468-15492)의 6차 디자인(531:17779)과 사용자의 Flutter/Supabase 지정에 따른 개정이다. [이전 PRD](archive/prd-v2.md)는 보존하며, 충돌하는 내용은 v3가 대체한다. 이 문서는 목표 요구사항이며 구현 완료를 뜻하지 않는다. 2026-09-30에 코드 기준 구현 현황(8절)과 PRD–구현 충돌(9절)을 추가했다.

## 1. 제품

Pind는 대한민국을 방문하거나 여행하는 사람이 자신의 음식 취향과 친구의 경험으로 식당·카페·베이커리·술집을 찾고 사진과 평가로 방문을 기록하는 iOS 우선 앱이다. 단일 인기 별점보다 개인의 선택 기준과 맛·양·분위기 평가를 함께 보여준다.

Flutter로 iOS/Android 코드를 공유한다. Supabase는 Auth, PostgreSQL, Storage, Edge Functions를 담당한다. 기존 Google Maps / Places API (New)를 유지한다. 서비스 장소 범위는 대한민국이며 국가 선택은 출신 국가·언어 선호다. Figma의 일본 장소명, 친구 수, 94%는 샘플이다. 가격은 원화 원본을 유지하고 환율 서비스 없이 숫자를 바꾸지 않는다. 출시 언어는 한국어/영어, 첫 화면 검증은 Figma 원문 한국어로 한다.

## 3. 핵심 여정

- J-01: 랜딩 → 공급자 로그인 → 국가 → 기본 정보/동의 → 닉네임·아이디 → 위치 안내 → 선택 기준 → 상황 → 음식 → 지도.
- J-02: 지도 → 출처/카테고리 → 사진 PIN → 축소 상세 → 펼친 소개/게시물 → 저장·공유·길찾기.
- J-03: 카테고리 → 부분 목록 → 전체 목록 → 내 취향/맛/양/분위기 정렬 → 상세 → 지도 상태 복원.
- J-04: 작성 → 장소 → 사진 → 3개 평가 → 글(선택) → 게시 → 상세/내 게시물/방문 지도 반영.
- J-05: Discover 커뮤니티/친구 → 장소·게시물·작성자. 친구 없으면 초대 안내.
- J-06: 마이페이지 내 지도·취향 수정·뱃지 / 저장·최근 본 장소 / 내 게시물.
- J-07: 친구 초대 → 로그인 → 상대 확인 → 요청/수락 → 양쪽 친구 콘텐츠. 주소록 업로드 제외.

## 4. 요구사항과 수용 기준

### 가입·취향

- FR-AU-001: 카카오/Apple/Google 로그인, 취소·실패·재시도, 세션 복원·로그아웃. 개발 익명 세션을 정식 인증으로 표시하지 않는다.
- FR-AU-002: 재인증 후 계정 삭제, 글·사진·저장·개인정보 정리와 처리 상태 안내.
- FR-OB-001: 국가 검색/선택과 언어 저장. 서비스 장소 범위는 한국임을 안내한다.
- FR-OB-002: 이름·생년월일·성별은 공개 프로필과 분리. 성별 미선택 지원. 필수 동의/14세 이상/선택 추천 동의를 구분하고 선택 동의 거부를 허용한다. 실제 약관의 용도·보유 기간과 일치해야 한다.
- FR-OB-003: 아이디는 대소문자 무시 중복 확인 + DB unique. 최종 확정 후 불변, 닉네임·아바타는 변경 가능.
- FR-TP-001: 선택 기준은 맛/분위기·공간/가성비/양/청결·서비스/사진 잘 나옴/조용함/주차 중 정확히 3개. 선택 순서가 순위이고 해제하면 순위 재계산. 기존 2개 draft는 보존하되 세 번째 선택을 요청한다.
- FR-TP-002: 혼밥/친구/데이트/가족/회식/작업/술/급할 때 중 0–3개. 0개로 진행 가능.
- FR-TP-003: 음식군 최소 3개. 사진 선택 표시·개수·버튼 활성화 일치, 모든 카드에 스크롤 접근 가능.
- FR-TP-004: 뒤로 가기·재시작에서 선택 복원, 프로필에서 수정 가능. 서버 저장 실패를 완료로 처리하지 않는다. P0 기기 draft는 임시 구현으로 구분한다.

### 공통 내비게이션 — 첫 구현 단위

- FR-NAV-001: 하단 아이콘 순서는 Discover / 지도 / 작성 / 마이페이지. 기본 선택은 지도. 선택 탭은 검정, 비선택/작성은 회색이며 아이콘 밑 라벨은 두지 않는다. 접근성 이름과 툴팁은 제공한다.
- FR-NAV-002: Figma 6차 디자인의 273×58, radius 29, 반투명 배경·blur 12·흰 테두리·얕은 그림자를 따른다. 화면 중앙 하단에 띄우고 홈 인디케이터/기기 safe area를 피한다. 각 터치 영역은 최소 44×44.
- FR-NAV-003: Discover/지도/마이페이지는 상태를 보존하는 탭이다. 탭 전환 시 지도 검색어·범위·카테고리·결과를 초기화하거나 새 API 조회를 강제하지 않는다.
- FR-NAV-004: 작성은 탭이 아닌 별도 화면 열기 동작이다. 닫으면 이전 탭/지도 상태로 돌아오고 중복 탭으로 작성 화면을 여러 개 쌓지 않는다. 전역 작성에서 장소를 임의 선택하지 않는다.
- FR-NAV-005: 온보딩·작성·상세 모달에서는 하단 내비게이션을 노출하지 않거나 해당 화면 아래에 둔다. 키보드가 열리면 숨긴다. 비지도 탭에서 시스템 뒤로 가기는 지도로 복귀한다.
- FR-NAV-006: 첫 단위는 내비게이션 외형/전환/상태 보존이다. Discover·마이페이지·작성 본문은 다음 단위이며 이번에는 구현 예정 안내를 명시한다. 가짜 피드·통계·게시 성공을 표시하지 않는다. (2026-09-30: 작성·Discover·마이페이지 본문 구현으로 ‘구현 예정’ 안내는 대체됨)

### 지도·검색·상세 요구사항

- FR-MAP-001: 네이티브 지도 위 검색바·출처 필터·사진 PIN·카테고리·내비게이션. Google 로고/저작권을 가리지 않는다.
- FR-MAP-002: 서울 기본 영역, 허용 시 현재 위치 이동. 수동 이동·현재 위치 복귀·확대·축소.
- FR-MAP-003: 전체/친구/저장/트렌드 중 하나. 친구는 수락된 관계의 공개 글, 저장은 본인 저장만.
- FR-MAP-004: 카테고리와 출처 조합. 카테고리 초기화는 사용자 취향을 삭제하지 않는다.
- FR-MAP-005: 로딩/빈 데이터/네트워크 실패/권한 거부/한국 범위 밖을 구분. 늦은 이전 응답이 새 결과를 덮어쓰지 않는다.
- FR-MAP-006: 장소당 PIN 1개, 사진 오류 fallback, 선택 강조, 터치 영역 최소 44pt.
- FR-MAP-007: 지도 하단의 ‘주변 N곳 보기’ 버튼은 표시하지 않는다. PIN을 눌러 상세를 열고, 명시적 검색·추가 검색 결과는 목록으로 열어 보완 장소도 선택할 수 있게 한다.
- FR-SR-001: 기본 검색·지도 탐색은 Supabase 공공/Pind 카탈로그를 조회한다. 공공 장소의 내부 ID는 재수입에도 유지하고, 사용자가 선택한 Google 후보만 서버 resolve로 별도 내부 ID를 확정한다.
- FR-SR-002: 자연어는 검색 조건으로 사용하되 메뉴·영업시간·알레르기 안전을 추정하지 않는다. AI 없이 기본 검색이 작동한다.
- FR-SR-003: 기본 검색/지도/공공 상세의 결과 없음·오류는 Google 호출을 자동 유발하지 않는다. 사용자가 ‘Google에서 추가 검색’을 선택했을 때만 유료 조회한다.
- FR-SR-004: Google 검색/resolve 응답에는 사진을 조회하지 않고 선택한 상세만 최대 1장을 조회한다. Google 내용은 요청/화면 메모리로 제한하며 영속 저장은 ID만 허용한다.
- FR-SR-005: 사용자/전체 일일 Google 외부 호출 횟수를 DB에서 원자적으로 제한하고 집계 실패 시 차단한다. 이는 금액 예산이 아니라 요청 수 제한이며 Google Console 한도와 함께 관리한다. 카카오/네이버 어댑터는 비활성 보존한다.
- FR-PL-001: 이름·주소·거리(권한 있을 때)·영업·사진 출처. 없는 정보는 미확인.
- FR-PL-002: 상세 축소/확장, 소개/게시물 탭, 저장/공유/길찾기. 배경 지도 상태 유지.
- FR-PL-003: 메뉴·요약·친구 방문 문구는 출처/관계/공개 범위가 검증된 데이터만.
- FR-PL-004: 저장 재탭 해제, 화면 간 일치, 실패 시 되돌림, 재시도 중복 방지.
- FR-PL-005: 공공/Pind 사진·소개·공개 게시물이 있으면 우선 표시한다. 원본 기준일을 구분하고 없는 사진·설명·시간·평점을 생성하지 않는다. 명시적으로 선택한 Google 상세는 실제 제공 정보와 필요한 출처를 표시한다.
- FR-PL-006: 공공/Pind 장소는 내부 ID로 저장/게시물과 연결한다. Google 추가 정보 찾기는 후보 선택 후 별도 출처의 상세를 열며, 이름·거리만으로 ID나 기존 게시물을 자동 병합하지 않는다. 비활성 카카오·네이버 결과는 기본 정보와 ‘운영시간 확인 필요’, 원본 링크만 허용한다.
- FR-PL-007: Figma `524:30239`와 첨부 이미지 기준의 유리 질감 확장형 상세 시트. 저장·공유·길찾기는 스크롤 밖 하단 SafeArea에 고정한다. 영업 상태 옆에 오늘의 시간, 실제 현재 위치의 직선거리, 출처의 리뷰 수를 표시한다. 위치/시간/리뷰 수가 없으면 미확인으로 구분한다.
- FR-PL-008: 수락된 친구의 해당 장소 공개 방문만 표시하고, 친구가 없거나 공개 방문이 없으면 친구 행을 숨긴다. 대기/해제 관계와 비공개 글은 제외한다. 친구 저장 수는 친구에게 공개한 저장만 집계한다.
- FR-PL-009: 2026-09-27 결정에 따라 우선 로컬 테스트 프로필로 친구 있음/없음/대기/해제/비공개 방문을 검증한다. 실제 Supabase Auth 테스트 계정은 아직 생성하지 않는다.

- FR-RC-004: 2026-10-01 사용자 승인 산식: 1·2·3순위 가중치 50·30·20%. 항목별 공개 평균 r(1–5)을 사용하며 내 평가도 다른 사람과 동일하게 평균에 한 번만 포함한다. 내 취향%=round(Σ((r−1)/4 × 순위 가중치)×100). 각 항목은 자신의 가중치만큼만 감점한다. 선택한 항목 평균이 하나라도 없으면 NULL(평가 부족)이며 가중치를 재분배하지 않는다. 최종 값만 일반 반올림한다. 맛·양·분위기 평균 4·3·2점은 58%. 친구 유사도 계산은 유지한다.

## 7. 디자인 해석과 외부 설정

프로토타입에는 시작점과 전체 화면 간 연결이 없고 메뉴 variant CHANGE_TO가 대부분이다. 위 여정은 화면 콘텐츠에서 도출한 설계이며 완전한 클릭 여정 검증은 아니다.

위치/선택 기준/상황/음식을 4단계로 정리한다. 중간 선택 기준 CTA는 ‘다음’, 마지막은 ‘내 취향 지도 만들기’로 정정한다. ‘양’ 설명 ‘바로 들어갈 수 있는’은 ‘한 끼에 충분한 양’으로 수정한다. [화면 분석](figma-screen-map.md)에 예시/중복/불일치를 기록한다.

로그인 공급자 설정, 정식 번들 ID/서명, 지도 SDK 제한 키, 공유 도메인, 실제 약관은 외부 준비 항목이다. 현재 프로젝트 자산의 재사용 여부부터 확인한다. [구현 설계](implementation-design.md)에 전환·데이터·검증 순서를 정의한다.
