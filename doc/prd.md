# pind_prd_v2

## 1. 제품 요약

Pind는 별점이 아닌 취향을 기준으로 음식점 정보를 탐색하는 iOS 모바일 앱이다. 여기서 음식점은 일반 식당뿐 아니라 카페, 베이커리, 디저트 매장 등 먹는 행위가 가능한 모든 공간을 포함한다.

기존 음식점 탐색 서비스는 광고, 불명확한 별점 기준, 대중적 인기 중심 랭킹 때문에 사용자의 실제 입맛과 맞지 않는 선택을 만들 수 있다. Pind는 맛, 식감, 분위기, 추천대상 같은 취향 기준을 사용해 사용자가 본인 또는 친구의 취향에 맞는 장소를 발견하도록 돕는다.

Pind의 첫 화면은 지도다. 지역에 등록된 음식점이 대표 음식 사진이 들어간 PIN으로 표시되고, 사용자는 전체보기, 추천, 내 국가 인기, 친구 추천, 트렌딩 필터로 지도를 탐색한다. 선택한 필터의 색상은 옵션 버튼과 PIN 테두리에 함께 적용되어 현재 보고 있는 탐색 맥락을 명확히 보여준다.

MVP에서는 식당에 대한 평가를 `게시물` 을 통해 하게된다. 게시물은 기존 식당 리뷰와 SNS의 게시물을 합친 형태이다. 게시물은 별점 평가가 아니라 사진, 취향 이모티콘, 맛·식감·분위기 태그, 자유 서술로 사용자의 음식 경험을 표현하는 콘텐츠다. 사용자가 게시물을 작성한 장소는 방문한 장소로 간주되어 마이페이지의 내 지도와 방문 기록에 반영된다.

MVP는 한국을 방문한 외국인이 대한민국 전역에서 본인 취향에 맞는 음식점, 카페, 베이커리, 디저트 공간을 쉽게 찾고, 방문 후 감각적인 게시물을 남기며, 이를 다른 SNS로 공유하는 흐름에 집중한다.

## 2. 확정된 제품 결정

- **D-001** Pind는 별점 기반 음식점 평가 앱이 아니라 취향 기반 음식점 탐색 앱이다.
- **D-002** Pind에서 음식점은 식당, 카페, 베이커리, 디저트 매장 등 먹는 행위가 가능한 모든 공간을 포함한다.
- **D-003** MVP의 1차 타겟은 한국을 방문한 외국인이며, 출시 지역은 대한민국이다.
- **D-004** MVP는 iOS 앱으로 우선 출시한다.
- **D-005** 첫 화면은 지도이며, 검색바, 필터 옵션, 음식 사진이 포함된 PIN, 하단 내비게이션을 포함한다.
- **D-006** 지도 기본 상태에서는 선택 지역에 등록된 모든 음식점을 PIN으로 표시한다.
- **D-007** 지도 필터는 `전체보기`, `추천`, `내 국가 인기`, `친구 추천`, `트렌딩`으로 시작한다.
- **D-008** 선택된 지도 필터의 색상은 필터 버튼과 결과 PIN 테두리에 동일하게 적용한다.
- **D-009** MVP 핵심 화면은 메인 지도, 음식점 상세, 피드, 게시물 등록, 마이페이지다.
- **D-010** MVP 로그인은 전화번호 로그인과 Apple 로그인을 지원한다.
- **D-011** MVP의 취향 기준은 맛, 식감, 분위기, 추천대상 네 축으로 시작한다.
- **D-012** MVP에서는 식당에 대한 평가를 `게시물` 하나의 기능으로 나타낸다.
- **D-013** Pind 게시물에는 별점 입력을 제공하지 않고, 이모티콘과 취향 태그로 경험을 표현한다.
- **D-014** 게시물은 기본 공개이며, 방문한 음식점 목록은 다른 유저가 볼 수 있다.
- **D-015** MVP에서 마이페이지 방문 기록 숨김 기능은 제공하지 않는다.
- **D-016** 사용자가 음식점에 게시물을 작성하면 해당 음식점을 방문한 것으로 간주한다.
- **D-017** 마이페이지는 `내 지도`, `저장`, `게시물` 3개 탭으로 구성한다.
- **D-018** 내 지도에는 사용자가 활동으로 얻은 뱃지와 방문한 장소의 사진 PIN을 표시한다.
- **D-019** 오늘 여정은 당일 방문 장소와 게시물을 순서형 지도 콘텐츠로 묶어 SNS 공유가 가능해야 한다.
- **D-020** 친구는 상호 수락 방식이며, 팔로우는 수락 없는 단방향 관계다. [해당 기능 구현은 우선 MVP에서 제외한다.]
- **D-021** MVP 알림은 필수 범위에서 제외한다.
- **D-022** 신고된 게시물과 비방글은 관리자 페이지에서 조치할 수 있어야 한다.  [해당 기능 구현은 우선 MVP에서 제외한다.]
- **D-023** 음식점과 지도 정보는 네이버 지도/장소 API 또는 카카오 지도/장소 API를 후보로 둔다.
- **D-024** 초기 데이터베이스는 Supabase 사용을 후보로 둔다.
- **D-025** 개인 맞춤형 음식 탐색 챗봇은 Pind의 핵심 방향이지만, MVP 포함 범위와 구현 수준은 추가 논의한다.
- **D-026** 지도 장소 조회 범위는 대한민국 전역이며, 지도를 이동한 뒤 현재 화면 영역을 기준으로 장소를 다시 조회한다.
- **D-027** Google 장소 사진은 메뉴 사진으로 간주하지 않는다. MVP 메뉴와 메뉴 사진은 메뉴명과 음식 사진이 포함된 Pind 게시물에서 구성한다.
- **D-028** 전역 게시물 작성 진입 시 장소를 임의로 기본 선택하지 않으며, 사용자가 Google 장소 검색으로 직접 선택해야 한다. 특정 장소 상세에서 작성할 때만 해당 장소를 미리 선택한다.
- **D-029** 메인 지도에는 확대·축소 컨트롤과 현재 위치 복귀 버튼을 제공한다. 현재 위치는 foreground 권한을 허용한 경우에만 화면 이동과 주변 장소 탐색에 사용하며 저장하지 않는다.

## 3. 목표와 성공 기준

### G-01. 별점이 아닌 취향 기반 음식점 탐색

사용자가 별점 순위가 아니라 본인의 맛, 식감, 분위기, 추천대상 취향을 기준으로 방문 후보를 찾을 수 있어야 한다.

### G-02. 외국인 친화적인 한국 음식점 발견

한국을 방문한 외국인이 한국어 음식점 정보에 익숙하지 않아도 대한민국 전역의 음식점, 카페, 베이커리, 디저트 공간을 쉽게 탐색할 수 있어야 한다.

### G-03. 지도 중심 탐색

사용자가 메인 지도에서 지역 내 음식점을 사진 PIN으로 보고, 전체보기·추천·내 국가 인기·친구 추천·트렌딩 필터로 빠르게 탐색할 수 있어야 한다.

### G-04. 친구 기반 신뢰 탐색

사용자가 친구가 방문했거나 게시물을 남긴 장소를 지도와 피드에서 모아볼 수 있어야 한다.

### G-05. 취향이 드러나는 게시물 작성

사용자가 별점 없이 사진, 이모티콘, 취향 태그, 자유 서술로 본인의 음식 경험을 표현할 수 있어야 한다.

### G-06. 방문 기록과 여정 공유

사용자가 방문한 장소를 마이페이지 내 지도에서 확인하고, 당일 방문 게시물을 오늘 여정으로 묶어 SNS에 공유할 수 있어야 한다.

### G-07. 추천 데이터 순환

사용자가 장소를 탐색하고, 방문하고, 게시물을 남기는 흐름이 반복되어 추천에 활용 가능한 데이터가 쌓여야 한다.

### G-08. 운영 가능한 공개 커뮤니티

게시물이 기본 공개되는 구조에서도 신고, 비방글 조치, 관리자 검토를 통해 서비스 품질을 유지할 수 있어야 한다.

## 4. 사용자와 화면

### 4.1 일반 사용자

- 전화번호 또는 Apple 로그인으로 가입·로그인한다.
- 온보딩 또는 프로필에서 본인의 음식 취향을 설정한다.
- 지도에서 전체보기, 추천, 내 국가 인기, 친구 추천, 트렌딩 필터로 음식점을 탐색한다.
- 음식점 상세에서 소개, 메뉴, 게시물, 메뉴별 취향 일치 정보를 확인한다.
- 피드에서 본인 맞춤 음식점과 친구가 남긴 게시물을 본다.
- 음식점 방문 후 게시물을 작성하고 사진과 취향 이모티콘, 취향 태그를 등록한다.
- 다른 사용자의 공개 마이페이지에서 친구 수, 팔로워, 팔로잉, 방문한 음식점, 게시물을 볼 수 있다.
- 친구 요청, 친구 삭제, 팔로우, 언팔로우, 신고를 할 수 있다.

### 4.2 친구

- 친구는 상호 수락으로 성립한다.
- 친구 관계가 성립되면 지도와 피드에서 친구가 방문하거나 게시물을 남긴 장소를 더 강하게 노출할 수 있다.
- 친구 기반 추천은 일반 팔로우 기반 추천보다 높은 신뢰 신호로 사용할 수 있다.

### 4.3 팔로워와 팔로잉

- 팔로우는 수락 없이 단방향으로 성립한다.
- 팔로워는 공개 게시물과 공개 방문 장소를 볼 수 있다.
- 팔로잉 목록은 사용자가 관심 있는 다른 사용자의 음식 취향을 따라가는 신호로 사용한다.

### 4.4 관리자

- 별도 관리자 페이지에서 로그인한다.
- 전체 유저, 음식점 데이터 연결 상태, 게시물, 신고 내역을 관리한다.
- 비방글, 허위 정보, 정책 위반 게시물을 유지, 숨김, 복구, 삭제 처리할 수 있다.
- 외부 API에서 가져온 장소 정보와 Pind 내부 장소 정보를 검토할 수 있다.

### 4.5 메인 지도 화면

- 앱 첫 화면이다.
- 상단 검색바를 제공한다.
- 검색바 아래에 `전체보기`, `추천`, `내 국가 인기`, `친구 추천`, `트렌딩` 필터 옵션을 제공한다.
- 기본 상태에서는 지역에 등록된 모든 음식점을 지도 위 PIN으로 표시한다.
- PIN에는 해당 음식점의 대표 음식 사진 또는 대표 이미지가 표시된다.
- 필터를 선택하면 선택된 옵션 버튼의 색상이 바뀐다.
- 필터 적용 결과 PIN의 테두리는 선택된 옵션 버튼과 같은 색상으로 표시된다.
- 하단 내비게이션으로 지도, 피드, 게시물 작성, 마이페이지 등 핵심 화면으로 이동한다.

### 4.6 음식점 상세 화면

- 음식점명, 대표 이미지, 위치, 운영 정보, 소개를 표시한다.
- 외부 API 또는 내부 DB에서 가져온 메뉴 정보를 표시한다.
- 메뉴별로 사용자의 취향과 얼마나 맞는지 보여준다.
- 해당 음식점에 연결된 게시물 목록을 표시한다.
- 음식점 공유, 저장, 게시물 작성 진입을 제공한다.

### 4.7 피드 화면

- 사용자 취향 기반 추천 음식점과 친구가 남긴 게시물을 제공한다.
- 별점 순위가 아니라 취향, 친구 활동, 트렌딩, 국가 기반 인기 신호를 조합해 노출한다.
- 게시물에서 음식점 상세 또는 작성자 마이페이지로 이동할 수 있다.

### 4.8 게시물 등록 화면

- MVP에서는 리뷰와 게시물을 하나의 `게시물` 작성 기능으로 제공한다.
- 사진 등록 영역은 작성 화면 최상단에 배치한다.
- 사용자는 음식점, 메뉴, 사진, 취향 이모티콘, 맛·식감·분위기 태그, 자유 서술을 입력한다.
- 별점 입력은 제공하지 않는다.
- 작성 완료 시 해당 음식점을 방문한 장소로 기록한다.
- 작성한 게시물은 기본 공개된다.

### 4.9 게시물 리스트 뷰

- 게시물 리스트 항목은 업로드 유저의 프로필 이미지, 닉네임, 좋아요 버튼을 포함한다.
- 사진은 카드가 서로 겹쳐진 형태로 표시한다.
- 화면에는 최대 3장의 사진을 표시하고, 4장 이상은 `+n`으로 표시한다.
- 가운데 사진에는 사용자가 선택한 취향 이모티콘을 표시한다.
- 하단에는 사용자가 선택한 맛, 식감, 분위기 태그를 표시한다.

### 4.10 마이페이지

- 마이페이지는 `내 지도`, `저장`, `게시물` 3개 탭으로 구성한다.
- 다른 사용자가 방문한 음식점 목록과 게시물을 볼 수 있다.
- MVP에서는 방문 기록 숨김 기능을 제공하지 않는다.

### 4.11 마이페이지 내 지도

- 사용자가 활동을 통해 얻은 뱃지를 표시한다.
- 지도에는 사용자가 다녀온 장소가 동그란 사진 PIN으로 표시된다.
- `앱 보기` 버튼을 누르면 메인 지도 화면으로 이동한다.
- 하단에는 오늘 여정 기능을 제공한다.

### 4.12 오늘 여정

- 사용자가 오늘 장소를 다녀오고 게시물을 남기면 해당 게시물을 오늘 여정에 추가할 수 있다.
- 오늘 여정은 가로선 형태로 표시하며 왼쪽에는 `START`, 오른쪽에는 `END`를 표시한다.
- 오늘 여정에 게시물을 추가하면 가로선 위에 순서대로 사진과 함께 나타난다.
- 공유 버튼을 누르면 지도 위에 오늘 여정 장소 사진이 표시된다.
- 공유 화면에서는 각 장소가 순서대로 점선으로 연결된다.
- 오늘 여정은 링크 또는 SNS로 공유할 수 있어야 한다.

## 5. 취향 기준과 핵심 개념

### 5.1 음식점 범위

Pind의 음식점은 일반 식당, 카페, 베이커리, 디저트 매장, 간식·음료·식사 등 먹는 경험을 제공하는 모든 공간을 포함한다.

### 5.2 취향 태그

| 축 | 태그 |
| --- | --- |
| 맛 | 매콤, 달콤, 짭짤, 담백, 고소, 새콤 |
| 식감 | 바삭, 쫄깃, 부드러운, 촉촉, 꾸덕 |
| 분위기 | 혼자가기 좋은, 친구와 가기 좋은, 조용, 현지 분위기 |
| 추천대상 | 한식 처음 먹는 사람, 매운 음식 좋아하는 사람, 저렴한 식사 선호인 |
- 취향 태그는 온보딩, 프로필, 게시물 작성 과정에서 수집할 수 있다.
- 사용자의 취향 정보는 추천과 메뉴별 취향 일치도 계산에 사용한다.
- 게시물에 붙은 취향 태그는 해당 음식점과 메뉴의 추천 신호로 사용한다.
- 게시물 리스트에서는 맛, 식감, 분위기 태그를 우선 표시한다.
- 취향 태그의 최종 개수, 다국어 표현, 가중치 계산 방식은 추가 논의한다.

### 5.3 취향 이모티콘

취향 이모티콘은 별점을 대체하는 감정적 표현 수단이다.

- 사용자는 게시물 작성 시 하나 이상의 취향 이모티콘을 선택할 수 있다.
- 게시물 리스트에서는 가운데 사진 위에 대표 이모티콘을 표시한다.
- 이모티콘은 음식점의 절대 점수가 아니라 사용자의 경험과 취향 반응을 표현한다.
- 이모티콘 종류, 의미, 추천 반영 방식은 추가 논의한다.

### 5.4 게시물

Pind의 MVP 작성 단위는 `게시물`이다. 게시물은 기존 음식점 리뷰의 정보성을 일부 포함하지만, 별점 리뷰가 아니라 취향과 경험을 표현하는 콘텐츠로 설계한다.

게시물은 다음 정보를 포함한다.

- 작성자
- 음식점
- 선택 메뉴
- 사진
- 취향 이모티콘
- 맛, 식감, 분위기, 추천대상 태그
- 자유 서술
- 작성 시각
- 공개 상태
- 좋아요 수
- 신고 상태

### 5.5 방문

MVP에서는 사용자가 특정 음식점에 게시물을 작성하면 해당 음식점을 방문한 것으로 간주한다.

방문 기록은 다음에 사용한다.

- 마이페이지 방문 음식점 표시
- 내 지도 사진 PIN 표시
- 오늘 여정 추가
- 친구 추천 신호
- 사용자 취향 학습
- 음식점별 게시물 집계

GPS 기반 방문 인증은 MVP에서 필수로 확정하지 않고 추가 논의 항목으로 둔다.

## 6. 핵심 사용자 여정

### J-01. 신규 사용자 온보딩과 탐색

1. 사용자가 앱을 실행한다.
2. 전화번호 또는 Apple 로그인으로 가입·로그인한다.
3. 온보딩에서 음식 취향을 선택한다.
4. 앱이 메인 지도 화면을 보여준다.
5. 사용자가 검색 또는 지도 필터로 음식점을 탐색한다.
6. 지도 PIN 또는 피드 카드에서 음식점을 선택한다.
7. 음식점 상세에서 소개, 메뉴, 게시물, 취향 일치 정보를 확인한다.
8. 사용자가 방문할 음식점을 결정한다.

### J-02. 취향 기반 지도 탐색

1. 사용자가 메인 지도에 진입한다.
2. 기본 상태에서는 지역에 등록된 모든 음식점 PIN을 본다.
3. 사용자가 전체보기, 추천, 내 국가 인기, 친구 추천, 트렌딩 중 하나를 선택한다.
4. 선택된 필터 버튼 색상이 변경된다.
5. 필터 결과에 해당하는 PIN 테두리가 같은 색상으로 변경된다.
6. 사용자가 PIN을 선택하면 음식점 요약 또는 상세 화면으로 이동한다.

### J-03. 음식점 상세 확인

1. 사용자가 지도 또는 피드에서 음식점을 선택한다.
2. 음식점 상세 화면이 열린다.
3. 사용자는 소개, 메뉴, 위치, 운영 정보, 게시물을 확인한다.
4. 사용자는 메뉴별 취향 일치 정보를 확인한다.
5. 사용자는 음식점을 저장하거나 공유하거나 방문 후보로 결정한다.

### J-04. 게시물 작성

1. 사용자가 실제 음식점 방문 후 작성 화면에 진입한다.
2. 음식점을 선택하거나 현재 상세 화면의 음식점이 자동 연결된다.
3. 사용자가 최상단 사진 영역에 음식 사진을 등록한다.
4. 사용자가 먹은 메뉴를 선택하거나 입력한다.
5. 사용자가 취향 이모티콘을 선택한다.
6. 사용자가 맛, 식감, 분위기, 추천대상 태그를 선택한다.
7. 사용자가 자유 서술을 작성한다.
8. 앱은 게시물이 기본 공개됨을 안내한다.
9. 사용자가 게시한다.
10. 해당 음식점은 사용자의 방문 장소로 기록된다.

### J-05. 게시물 탐색과 공유

1. 사용자가 피드, 음식점 상세, 마이페이지에서 게시물 리스트를 본다.
2. 게시물 카드에서 작성자, 사진, 취향 이모티콘, 태그, 좋아요를 확인한다.
3. 사용자는 게시물을 좋아요하거나 공유할 수 있다.
4. 공유 시 앱 딥링크 또는 웹 미리보기로 연결되는 공유 링크가 생성된다.

### J-06. 마이페이지 내 지도와 오늘 여정

1. 사용자가 마이페이지의 `내 지도` 탭을 연다.
2. 사용자는 활동 뱃지와 방문 장소 사진 PIN을 확인한다.
3. 사용자가 오늘 작성한 게시물을 오늘 여정에 추가한다.
4. 오늘 여정은 `START`에서 `END`까지 가로선 위에 게시물 사진을 순서대로 표시한다.
5. 사용자가 공유 버튼을 누른다.
6. 앱은 지도 위 장소 사진과 점선 연결을 포함한 공유 화면을 생성한다.
7. 사용자는 오늘 여정을 링크 또는 SNS로 공유한다.

### J-07. 친구 기반 탐색

1. 사용자가 친구 요청을 보낸다.
2. 상대 사용자가 친구 요청을 수락한다.
3. 두 사용자는 친구 관계가 된다.
4. 지도와 피드에서 친구가 방문하거나 게시물을 남긴 음식점이 노출된다.
5. 사용자는 친구의 공개 마이페이지에서 방문 음식점과 게시물을 확인한다.

### J-08. 팔로우 기반 탐색

1. 사용자가 다른 사용자를 팔로우한다.
2. 상대방의 수락 없이 팔로잉 관계가 생성된다.
3. 사용자는 팔로잉한 사용자의 공개 게시물과 방문 음식점을 볼 수 있다.
4. 팔로잉 관계는 추천 신호로 사용할 수 있다.

### J-09. 신고와 관리자 조치

1. 사용자가 비방글, 허위 정보, 부적절한 게시물을 신고한다.
2. 신고 내역이 관리자 페이지에 생성된다.
3. 관리자는 신고된 게시물과 신고 사유를 확인한다.
4. 관리자는 게시물을 유지, 숨김, 복구 또는 삭제 처리한다.
5. 처리 결과는 감사 이력에 남는다.

## 7. 기능 요구사항

### 7.0 화면 경로

- **FR-RT-001** 앱은 iOS 모바일 앱으로 제공한다.
- **FR-RT-002** 앱의 기본 진입 화면은 메인 지도 화면이다.
- **FR-RT-003** 앱은 메인 지도, 음식점 상세, 피드, 게시물 등록, 마이페이지 화면을 제공한다.
- **FR-RT-004** 관리자 기능은 일반 사용자 앱 화면과 분리된 관리자 페이지에서 제공한다.

### 7.1 로그인과 온보딩

- **FR-AUTH-001** 사용자는 전화번호 또는 Apple 로그인으로 가입·로그인할 수 있다.
- **FR-AUTH-002** 로그인하지 않은 사용자는 개인화 추천, 친구, 팔로우, 게시물 작성, 마이페이지 기능을 사용할 수 없다.
- **FR-AUTH-003** 사용자는 온보딩 또는 프로필에서 음식 취향을 설정할 수 있어야 한다.
- **FR-AUTH-004** 온보딩 취향 수집 화면은 맛, 식감, 분위기, 추천대상 축을 반영해야 한다.
- **FR-AUTH-005** 사용자는 프로필에서 취향 정보를 수정할 수 있어야 한다.

### 7.2 지도와 음식점 탐색

- **FR-MAP-001** 메인 화면은 지도 기반으로 렌더링한다.
- **FR-MAP-002** 지도 상단에는 장소, 메뉴, 분위기 검색이 가능한 검색바를 제공한다.
- **FR-MAP-003** 검색바 아래에는 전체보기, 추천, 내 국가 인기, 친구 추천, 트렌딩 필터를 제공한다.
- **FR-MAP-004** 기본 상태의 전체보기에서는 지역에 등록된 모든 음식점 PIN을 표시한다.
- **FR-MAP-005** 지도에는 음식점 위치에 맞는 PIN을 표시한다.
- **FR-MAP-006** PIN에는 음식점 대표 음식 사진 또는 대표 이미지를 표시한다.
- **FR-MAP-007** 필터를 선택하면 선택된 옵션 버튼이 특정 색으로 변경된다.
- **FR-MAP-008** 필터 결과 PIN의 테두리는 선택된 옵션 버튼과 같은 색으로 표시한다.
- **FR-MAP-009** 사용자가 PIN을 선택하면 음식점 요약 또는 상세 화면으로 이동할 수 있어야 한다.
- **FR-MAP-010** 지도는 현재 위치 권한을 사용해 주변 음식점을 탐색할 수 있어야 한다.
- **FR-MAP-011** 위치 권한을 거부해도 검색과 수동 지도 이동을 통한 탐색은 가능해야 한다.

### 7.3 검색과 필터

- **FR-SR-001** 사용자는 장소명, 메뉴명, 분위기 키워드로 검색할 수 있어야 한다.
- **FR-SR-002** 전체보기는 선택 지역 또는 현재 지도 영역의 모든 등록 음식점을 표시한다.
- **FR-SR-003** 추천 필터는 사용자 취향과 행동 데이터를 기반으로 음식점을 정렬한다.
- **FR-SR-004** 내 국가 인기 필터는 사용자의 국가 또는 언어권 사용자에게 인기 있는 음식점을 우선 노출한다.
- **FR-SR-005** 친구 추천 필터는 친구가 방문하거나 게시물을 남긴 음식점을 우선 노출한다.
- **FR-SR-006** 트렌딩 필터는 최근 저장, 방문, 게시물 작성, 공유가 증가한 음식점을 우선 노출한다.

### 7.4 음식점 상세

- **FR-PL-001** 음식점 상세는 음식점명, 대표 이미지, 위치, 소개, 운영 정보, 메뉴, 게시물을 포함한다.
- **FR-PL-002** 음식점 소개와 기본 정보는 외부 장소 API 또는 내부 DB에서 가져온다.
- **FR-PL-003** 메뉴 정보가 외부 API에서 제공되지 않으면 내부 DB 또는 사용자 작성 데이터를 통해 보완할 수 있어야 한다.
- **FR-PL-004** 각 메뉴에는 사용자의 취향과 얼마나 일치하는지 보여주는 정보를 제공해야 한다.
- **FR-PL-005** 음식점 상세에서 저장, 공유, 게시물 작성 진입을 제공한다.
- **FR-PL-006** 음식점 상세의 게시물 목록은 최신순 또는 추천순으로 볼 수 있어야 한다.

### 7.5 취향 기반 추천

- **FR-RC-001** 추천은 별점이 아니라 사용자 취향 태그와 행동 신호를 기반으로 한다.
- **FR-RC-002** MVP 추천은 맛, 식감, 분위기, 추천대상 태그를 기본 입력으로 사용한다.
- **FR-RC-003** 사용자의 저장, 방문, 게시물 작성, 친구 활동은 추천 신호로 사용할 수 있다.
- **FR-RC-004** 같은 국가 또는 같은 언어권 사용자의 선호는 추천 신호로 사용할 수 있다.
- **FR-RC-005** 추천 결과에는 사용자가 왜 이 음식점을 추천받았는지 이해할 수 있는 설명을 제공해야 한다.
- **FR-RC-006** 추천 알고리즘의 정확한 가중치와 계산 방식은 추가 논의한다.

### 7.6 개인 맞춤형 음식 탐색 챗봇

- **FR-CH-001** 사용자는 텍스트 또는 음성으로 음식점 추천을 요청할 수 있어야 한다.
- **FR-CH-002** 챗봇은 사용자의 취향, 위치, 시간대, 음식 종류, 예산, 동행 맥락을 고려해 음식점을 추천할 수 있어야 한다.
- **FR-CH-003** 챗봇 추천 결과는 Pind 내부 음식점 상세와 연결되어야 한다.
- **FR-CH-004** 챗봇의 MVP 포함 여부, 텍스트·음성 범위와 구현 수준은 추가 논의한다.
- **FR-CH-005** 챗봇은 음식점의 실제 운영 여부, 메뉴, 위치 정보가 불확실한 경우 확정적으로 표현하지 않아야 한다.

### 7.7 게시물 작성

- **FR-PO-001** MVP에서는 리뷰와 게시물을 하나의 게시물 작성 기능으로 제공한다.
- **FR-PO-002** 사진 등록 영역은 게시물 작성 화면의 최상단에 배치한다.
- **FR-PO-003** 사용자는 음식점, 메뉴, 사진, 취향 이모티콘, 취향 태그, 자유 서술을 입력할 수 있어야 한다.
- **FR-PO-004** 게시물에는 별점 입력을 제공하지 않는다.
- **FR-PO-005** 사용자는 맛, 식감, 분위기, 추천대상 태그를 선택할 수 있어야 한다.
- **FR-PO-006** 게시물 작성 완료 시 해당 음식점은 사용자의 방문 장소로 기록된다.
- **FR-PO-007** 게시물은 기본 공개된다.
- **FR-PO-008** 게시물은 외부 SNS로 공유할 수 있어야 한다.
- **FR-PO-009** 사용자는 본인이 작성한 게시물을 수정 또는 삭제할 수 있어야 한다.

## 8. 상태와 핵심 모델

MVP에서 복잡한 업무 상태 모델은 최소화한다. 다만 신고, 친구 요청, 팔로우, 게시물 공개 상태는 운영상 필수이므로 최소 상태를 둔다.

### 8.1 게시물 상태

```
active → reported → hidden
   ↑          ↘       ↘
   └──────── restored  deleted
```

| 내부값 | 표시 | 의미 |
| --- | --- | --- |
| `active` | 공개 중 | 정상 공개 상태 |
| `reported` | 신고됨 | 신고가 접수되어 관리자 검토가 필요한 상태 |
| `hidden` | 숨김 | 관리자 조치로 일반 사용자에게 보이지 않는 상태 |
| `restored` | 복구됨 | 숨김 또는 신고 상태에서 다시 공개된 상태 |
| `deleted` | 삭제됨 | 작성자 또는 관리자가 삭제한 상태 |
- 신고만으로 즉시 삭제하지 않는다.
- 관리자는 신고된 콘텐츠를 유지, 숨김, 복구, 삭제할 수 있다.
- 작성자가 삭제한 게시물은 일반 사용자에게 노출하지 않는다.
- 관리자 조치 이력은 보존한다.

### 8.2 친구 요청 상태

```
pending → accepted
   ↘        ↘
 declined  removed
```

| 내부값 | 표시 | 의미 |
| --- | --- | --- |
| `pending` | 요청 중 | 친구 요청을 보낸 상태 |
| `accepted` | 친구 | 상대방이 수락한 상태 |
| `declined` | 거절됨 | 상대방이 거절한 상태 |
| `removed` | 삭제됨 | 한쪽 사용자가 친구 관계를 삭제한 상태 |

### 8.3 팔로우 상태

```
following → unfollowed
```

| 내부값 | 표시 | 의미 |
| --- | --- | --- |
| `following` | 팔로잉 | 사용자가 다른 사용자를 팔로우 중인 상태 |
| `unfollowed` | 팔로우 취소 | 팔로우가 해제된 상태 |

### 8.4 오늘 여정 상태

```
draft → shared
  ↘       ↘
 expired  deleted
```

| 내부값 | 표시 | 의미 |
| --- | --- | --- |
| `draft` | 작성 중 | 오늘 여정에 게시물을 추가하고 있는 상태 |
| `shared` | 공유됨 | 공유 링크 또는 공유 이미지가 생성된 상태 |
| `expired` | 종료됨 | 오늘 기준 시간이 지나 더 이상 오늘 여정으로 수정하지 않는 상태 |
| `deleted` | 삭제됨 | 사용자가 여정을 삭제한 상태 |

## 9. 데이터와 권한 경계

### 9.1 정본 데이터

- **사용자:** 이름, 국가, 언어, 프로필 이미지, 로그인 식별자, 가입 시각
- **사용자 개인정보:** 전화번호, Apple 계정 식별자, 연락처 기반 친구 추천 정보
- **취향 프로필:** 맛, 식감, 분위기, 추천대상 태그와 수정 이력
- **음식점:** 외부 API 장소 ID, 이름, 주소, 좌표, 카테고리, 대표 이미지, 소개, 운영 정보
- **메뉴:** 음식점, 메뉴명, 설명, 가격, 이미지, 취향 태그
- **게시물:** 작성자, 음식점, 메뉴, 사진, 취향 이모티콘, 취향 태그, 본문, 공개 상태, 작성 시각
- **게시물 반응:** 좋아요, 공유, 신고, 작성·취소 시각
- **방문 기록:** 사용자, 음식점, 연결 게시물, 방문 간주 시각
- **오늘 여정:** 사용자, 기준 날짜, 연결 게시물 순서, 공유 상태, 공유 링크 또는 이미지
- **저장 장소:** 사용자, 음식점, 저장 시각
- **친구 관계:** 요청자, 수신자, 상태, 요청·수락·삭제 시각
- **팔로우 관계:** 팔로워, 팔로잉 대상, 상태, 생성·해제 시각
- **신고:** 신고자, 대상 게시물, 신고 사유, 처리 상태, 관리자 조치
- **관리자 계정:** 관리자 식별자, 권한, 활성 여부, 로그인 이력
- **추천 로그:** 추천 입력값, 추천 결과, 노출, 클릭, 저장, 방문, 작성 전환

### 9.2 공개 데이터

- 사용자 프로필의 공개 정보
- 친구 수, 팔로워 수, 팔로잉 수
- 사용자가 방문한 음식점 목록
- 사용자가 작성한 공개 게시물
- 음식점별 공개 게시물
- 음식점 기본 정보
- 공개 공유 링크로 생성된 오늘 여정

### 9.3 비공개 데이터

- 전화번호
- Apple 계정 식별자
- 연락처 원본 데이터
- 위치 권한 기반 현재 위치
- 관리자 조치 이력 중 내부 메모
- 추천 알고리즘 내부 가중치와 로그
- 신고자의 식별 정보

### 9.4 권한 원칙

- 일반 사용자는 공개 게시물과 공개 마이페이지를 볼 수 있다.
- 일반 사용자는 다른 사용자의 전화번호, 연락처, 로그인 식별자, 현재 위치를 볼 수 없다.
- 사용자는 본인이 작성한 게시물만 수정 또는 삭제할 수 있다.
- 사용자는 다른 사용자의 게시물을 신고할 수 있지만 직접 숨기거나 삭제할 수 없다.
- 관리자는 운영 목적상 필요한 범위에서 전체 유저, 게시물, 신고 내역을 볼 수 있다.
- 관리자 접근과 조치 이력은 감사 로그로 남긴다.
- 연락처 기반 친구 추천을 사용할 경우 명시적 권한 요청과 목적 고지가 필요하다.
- Supabase를 사용할 경우 노출 스키마의 사용자 데이터 테이블은 RLS를 활성화하고, 공개 클라이언트에 service role 또는 secret key를 제공하지 않는다.

## 10. 비기능 요구사항

### 10.1 보안·개인정보

- 전화번호, Apple 계정 식별자, 연락처 정보는 일반 사용자에게 공개하지 않는다.
- 연락처 접근은 친구 추천 목적을 명확히 안내한 뒤 사용자 동의가 있을 때만 요청한다.
- 위치 권한은 주변 음식점 탐색과 방문 인증 후보 기능에만 사용한다.
- 서비스 로그에 전화번호, 연락처 원본, 위치 좌표, 인증 토큰을 평문으로 기록하지 않는다.
- 게시물 사진 업로드 시 파일 형식, 크기, 악성 파일 여부를 검증한다.
- 관리자 페이지는 일반 사용자 앱과 분리하고 별도 인증을 적용한다.

### 10.2 신뢰와 커뮤니티 품질

- 게시물은 기본 공개이므로 신고 기능을 제공한다.
- 신고만으로 콘텐츠를 즉시 삭제하지 않고 관리자 검토를 거친다.
- 반복 허위 정보 작성자, 악성 신고자, 비방글 작성자에 대한 운영 정책이 필요하다.
- 추천 품질이 낮은 경우 사용자가 피드백을 줄 수 있는 구조를 후속 검토한다.

### 10.3 성능

- 메인 지도는 현재 viewport와 선택 필터에 필요한 PIN만 요청한다.
- 지도 PIN 이미지는 썸네일로 최적화한다.
- 음식점 상세 화면은 기본 정보와 게시물을 단계적으로 로딩할 수 있다.
- 피드는 서버 페이지네이션을 사용한다.
- 추천 결과는 반복 요청 시 캐싱할 수 있다.

### 10.4 접근성·외국인 사용성

- 핵심 UI는 한국을 처음 방문한 외국인도 이해할 수 있는 쉬운 표현을 사용한다.
- 지도 PIN, 필터, 취향 태그는 색만으로 구분하지 않는다.
- 음식점명, 메뉴명, 주소의 한국어 표기에 대한 보조 설명 또는 번역을 고려한다.
- 터치 대상은 모바일에서 충분한 크기로 제공한다.
- 위치 권한 거부, API 실패, 검색 결과 없음, 업로드 실패 상황을 명확히 안내한다.

### 10.5 운영·복구

- 외부 지도/장소 API 장애 시 사용자에게 탐색 제한을 안내한다.
- 장소 정보 동기화 실패와 중복 장소 연결 문제를 관리자에서 확인할 수 있어야 한다.
- 게시물 사진 저장 실패 시 게시 완료로 처리하지 않는다.
- DB와 사진 저장소는 백업과 복구 전략을 가져야 한다.

## 11. 검증 시나리오

### 11.1 지도 탐색

- 앱 실행 후 첫 화면이 지도 화면으로 열린다.
- 검색바와 필터 옵션이 지도 상단에 표시된다.
- 전체보기, 추천, 내 국가 인기, 친구 추천, 트렌딩 필터가 표시된다.
- 전체보기에서는 지역 내 모든 등록 음식점 PIN이 표시된다.
- 필터 선택 시 옵션 버튼 색상과 PIN 테두리 색상이 함께 변경된다.
- 지도 PIN에 음식점 대표 이미지가 표시된다.
- PIN 선택 시 음식점 상세로 이동한다.
- 위치 권한을 거부해도 수동 탐색이 가능하다.

### 11.2 음식점 상세

- 음식점 상세에서 소개, 메뉴, 게시물을 볼 수 있다.
- 메뉴별 취향 일치 정보가 표시된다.
- 음식점 저장과 공유가 가능하다.
- 음식점 상세에서 게시물 작성 화면으로 이동할 수 있다.

### 11.3 게시물 작성과 리스트

- 사용자는 음식점, 메뉴, 사진, 취향 이모티콘, 취향 태그, 자유 서술을 입력해 게시물을 작성할 수 있다.
- 게시물 작성에는 별점 입력이 없다.
- 사진 등록 영역은 작성 화면 최상단에 있다.
- 작성 완료 후 해당 음식점이 방문한 장소로 기록된다.
- 작성된 게시물은 기본 공개된다.
- 작성자는 본인 게시물을 수정 또는 삭제할 수 있다.
- 게시물 리스트에는 작성자 프로필 이미지, 닉네임, 좋아요 버튼이 표시된다.
- 게시물 사진은 겹쳐진 카드 형태이며 최대 3장과 `+n` 표시 규칙을 따른다.
- 가운데 사진에는 취향 이모티콘이 표시된다.
- 게시물 하단에는 맛, 식감, 분위기 태그가 표시된다.

### 11.4 마이페이지와 오늘 여정

- 마이페이지에는 내 지도, 저장, 게시물 탭이 표시된다.
- 내 지도에는 활동 뱃지가 표시된다.
- 내 지도에는 방문한 장소가 동그란 사진 PIN으로 표시된다.
- 앱 보기 버튼을 누르면 메인 지도 화면으로 이동한다.
- 사용자는 오늘 작성한 게시물을 오늘 여정에 추가할 수 있다.
- 오늘 여정은 START와 END가 있는 가로선 위에 사진을 순서대로 표시한다.
- 오늘 여정 공유 화면은 지도 위 장소 사진과 점선 연결을 포함한다.
- 오늘 여정을 링크 또는 SNS로 공유할 수 있다.

### 11.5 친구와 팔로우

- 친구 요청은 상대방 수락 전까지 `pending` 상태다.
- 상대방이 수락하면 친구 관계가 된다.
- 사용자는 친구를 삭제할 수 있다.
- 팔로우는 상대방 수락 없이 즉시 성립한다.
- 언팔로우 시 팔로우 관계가 해제된다.
- 마이페이지에 친구 수, 팔로워 수, 팔로잉 수가 표시된다.

### 11.6 공개 범위

- 다른 사용자는 공개 마이페이지에서 방문한 음식점과 게시물을 볼 수 있다.
- 다른 사용자는 전화번호, 연락처, 로그인 식별자, 현재 위치를 볼 수 없다.
- MVP에서는 방문 기록 숨김 기능이 제공되지 않는다.

### 11.7 신고와 관리자 조치

- 사용자는 게시물을 신고할 수 있다.
- 신고된 게시물은 관리자 페이지에 표시된다.
- 관리자는 신고된 게시물을 유지, 숨김, 복구, 삭제 처리할 수 있다.
- 관리자 조치 이력이 남는다.
- 숨김 또는 삭제된 게시물은 일반 사용자에게 노출되지 않는다.

### 11.8 추천

- 추천 결과는 별점이 아니라 사용자 취향 태그와 행동 신호를 기반으로 한다.
- 사용자의 취향 태그가 바뀌면 추천 결과에 영향을 줄 수 있다.
- 친구가 방문하거나 게시물을 남긴 장소는 친구 추천에 반영된다.
- 추천 결과에는 추천 이유가 표시된다.

## 12. 출시 단계

1. **기초 앱 구조:** iOS 앱, 로그인, 메인 지도, 하단 내비게이션, 기본 마이페이지
2. **장소 탐색:** 네이버/카카오 지도 후보 연동, 음식점 PIN, 검색, 필터, 음식점 상세
3. **취향 모델:** 온보딩 취향 수집, 취향 태그, 취향 이모티콘, 메뉴·음식점 취향 일치 표시
4. **게시물:** 사진 업로드, 취향 이모티콘, 취향 태그 작성, 자유 서술, 방문 기록 생성, 공유
5. **마이페이지:** 내 지도, 저장, 게시물 탭, 뱃지, 방문 장소 사진 PIN, 오늘 여정
6. **소셜 관계:** 친구 요청·수락·삭제, 팔로우·언팔로우, 친구 추천, 공개 마이페이지
7. **운영 관리:** 신고, 관리자 페이지, 게시물 숨김·복구·삭제, 감사 로그
8. **추천 고도화:** 취향 기반 추천 알고리즘, 국가별 인기, 트렌딩, 추천 이유
9. **AI 탐색:** 텍스트 기반 챗봇, 음성 입력 검토, 추천 결과와 음식점 상세 연결

각 단계는 정적 목업이 아니라 실제 데이터 저장, 조회, 권한 검증, 실패 처리까지 연결된 뒤 완료로 본다.

Pind MVP는 다음이 모두 충족된 뒤 파일럿 준비 완료로 본다.

- iOS 앱에서 전화번호 또는 Apple 로그인으로 가입·로그인이 가능하다.
- 사용자가 취향 태그를 설정하고 수정할 수 있다.
- 지도 첫 화면에서 음식점 PIN, 검색바, 필터, 하단 내비게이션이 동작한다.
- 전체보기, 추천, 내 국가 인기, 친구 추천, 트렌딩 필터가 동작한다.
- 필터 선택 색상과 PIN 테두리 색상이 일관되게 반영된다.
- 음식점 상세에서 소개, 메뉴, 게시물, 메뉴별 취향 일치 정보를 볼 수 있다.
- 사용자가 음식점에 게시물을 작성하고 사진을 등록할 수 있다.
- 게시물 작성에 별점이 없고, 취향 이모티콘과 취향 태그를 사용할 수 있다.
- 게시물 작성 후 해당 음식점이 방문한 장소로 기록된다.
- 게시물 리스트가 프로필, 닉네임, 좋아요, 겹친 사진 카드, 취향 이모티콘, 태그를 표시한다.
- 마이페이지에 내 지도, 저장, 게시물 탭이 있다.
- 내 지도에서 방문 장소 사진 PIN과 뱃지를 볼 수 있다.
- 오늘 여정을 만들고 링크 또는 SNS로 공유할 수 있다.
- 게시물과 음식점을 외부 SNS로 공유할 수 있다.
- 친구 요청, 수락, 삭제가 동작한다.
- 팔로우와 언팔로우가 동작한다.
- 다른 사용자의 공개 마이페이지에서 방문 음식점과 게시물을 볼 수 있다.
- 다른 사용자의 전화번호, 연락처, 로그인 식별자, 현재 위치는 조회할 수 없다.
- 신고된 게시물을 관리자가 숨김, 복구, 삭제 처리할 수 있다.
- 추천 결과가 최소한 취향 태그와 친구 활동을 반영한다.
- 외국인 사용자가 대한민국 전역에서 음식점 탐색, 상세 확인, 방문 후 게시물 작성 흐름을 완료할 수 있다.
