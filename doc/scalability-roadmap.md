# 확장성 로드맵

Pind가 서울·포항 MVP를 넘어 사용자·데이터·지역 단위로 확장되려면 추가해야 할 요소와 진행 상태를 기록한다.

최초 작성: 2026-10-07

## 업데이트 규칙

- 아래 항목에 해당하는 작업을 시작·완료하면 같은 커밋에서 이 문서의 **상태**와 **메모**를 갱신한다.
- 상태: `대기` → `진행` → `완료` (보류 시 `보류`와 이유).
- 완료 시 메모에 날짜와 근거(마이그레이션·파일·PR)를 남긴다. 측정·검증하지 않은 것은 완료로 쓰지 않는다.
- 새 병목·요건을 발견하면 해당 단계에 항목을 추가한다. 단계 D 항목은 **도입 조건**이 충족됐다는 측정 근거가 있을 때만 위 단계로 올린다.
- 맨 아래 [변경 이력](#변경-이력)에 한 줄을 추가한다.

## 1. 현재 상태 (2026-10-07 기준)

### 핵심 가치

- **취향 점수**: 8개 기준(맛·분위기·가성비·양·청결·사진·조용함·주차) 중 우선순위 3개에 50:30:20 가중치 ([취향 계산](taste-calculation.md)).
- **공공데이터 우선 + 비용 통제**: 소상공인 데이터 서울 141,126건·포항 10,175건. Google Places는 보완용. 외부 API는 `take_external_request_budget`로 사용자별·전체 일일·분당 한도.
- **AI**: 리뷰 인사이트(`supabase/functions/places/insights.ts`), 자연어 에이전트 검색(`agent.ts`). Groq 우선, Gemini 폴백.
- **다국어**: ko/en/ja/zh-Hans/zh-Hant, 영문 주소·식당명 영문화 파이프라인.

### 기술 구조

- 클라이언트: Flutter MVC ([아키텍처](architecture.md)). 서비스 인터페이스 + Supabase 구현체, `main.dart`에서 `AppController`에 주입.
- 서버: Supabase(Postgres 17 + PostGIS), 마이그레이션 43개, `security invoker` RPC + RLS, Storage, Edge Function `places`·`google-places`.
- 이미 갖춘 것: 게시물 발행 멱등성과 실패 시 파일 정리, 요청 타임아웃·취소(`RequestClient`), 피드 커서 페이지네이션, 장소 집계 카운터(`place_rating_stats`, `public_post_count`), 지도 핀 클러스터링, AI 요약 백그라운드 생성(`waitUntil` + claim 잠금 + 실패 후 1분 대기).
- 테스트: Flutter 46개 파일(단위·위젯 40, 통합 6), SQL 21개, Deno 테스트. **CI 없음.**
