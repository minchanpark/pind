# Pind 취향 점수 안내

Pind는 "내 취향 별점"을 하나 만들고, 그것으로 식당 취향 %와 친구 취향 %를 계산합니다. 이 문서는 계산 방법을 쉬운 예시로 설명하고, 맨 아래에 개발 기준을 정리합니다.

설계 날짜: 2026년 10월 11일 (이전 설계: 2026년 10월 1일 50·30·20 고정 방식)

상태: 앱 코드와 SQL 마이그레이션(`20261011000000_taste_stars.sql`)에 구현했고, 로컬 SQL·Flutter 테스트를 통과했습니다. 2026년 10월 11일 QA 시드를 지운 뒤 운영 DB에 적용하고 임시 계정으로 `get_my_taste`·친구 %·AI 검색 호출을 확인했습니다. 적용 시점의 공개 별점은 15개뿐이라, 실제 별점 분포에 맞춘 조정은 데이터가 쌓인 뒤 합니다. 이 계산을 쓰는 앱 빌드는 아직 배포 전입니다.

## 1. 세 가지 점수

| 점수 | 무엇을 보여주나 |
|---|---|
| 내 취향 별점 | 내가 식당에 바라는 8개 기준별 별점 묶음 |
| 식당 취향 % | 이 식당이 내 별점을 얼마나 채우는지 |
| 친구 취향 % | 친구의 별점 묶음과 내 별점 묶음이 얼마나 닮았는지 |

세 점수 모두 내 취향 별점에서 출발합니다. 그래서 내 취향이 바뀌면 식당 %와 친구 %도 함께 바뀝니다.

## 2. "모두 4점대" 문제와 환산 별점

Pind 별점은 대부분 4점대에 모입니다. 시험이 쉬워서 모두 90점대를 받는 상황과 같습니다. 별점을 그대로 비교하면 쓸수록 모든 식당과 모든 친구가 비슷한 %로 보입니다.

그래서 별점을 "Pind 전체 평균보다 얼마나 나은가"로 바꿔 비교합니다. 이것을 환산 별점이라고 부릅니다.

- 전체 평균과 같으면 3점, 5점이면 5점, 1점이면 1점
- 그 사이는 고르게 늘이거나 줄입니다

```text
별점 r이 평균 g보다 높을 때:  3 + 2 × (r − g) / (5 − g)
별점 r이 평균 g보다 낮을 때:  3 − 2 × (g − r) / (g − 1)
평균이 아직 없으면 3
```

예: 맛의 전체 평균이 4.3이면 4.0 → 2.8, 4.3 → 3.0, 4.7 → 4.1, 5.0 → 5.0

화면에는 원래 별점을 보여주고, 환산 별점은 계산에만 씁니다.

## 3. 내 취향 별점

### 출발점

로그인할 때 고른 우선순위 3개가 시작 별점이 됩니다.

| 순위 | 1순위 | 2순위 | 3순위 | 나머지 |
|---|---|---|---|---|
| 시작 별점 | 5.0 | 4.2 | 3.8 | 3.0 (보통) |

### 중요도

중요도는 "3점(보통)보다 얼마나 높게 바라는가"에 비례합니다. 시작 별점의 중요도는 2.0 : 1.2 : 0.8, 즉 정확히 50 : 30 : 20입니다. 처음에는 고정 가중치 50·30·20이 붙습니다.

### 기록이 쌓이면

증거는 두 가지입니다. 모두 환산 별점으로 바꿔 씁니다.

- 내가 게시물을 쓰며 준 별점 (비공개 게시물 포함: 내 취향 계산에만 쓰입니다)
- 내가 저장한 식당의 기준별 공개 평균 별점

한 식당은 기준마다 한 번만 셉니다. 내가 별점을 준 기준이면 저장한 식당의 평균 대신 내 별점을 씁니다. 좋아요한 게시물은 쓰지 않습니다.

```text
내 별점 = 시작 별점 + α × (증거 평균 − 시작 별점)
α = min(n / (10 + n), 1/2)      n = 그 기준의 증거 식당 수
```

| 증거 식당 수 | 0곳 | 5곳 | 8곳 | 10곳 이상 |
|---|---|---|---|---|
| 기록 반영 비율 | 0% | 33% | 44% | 50% (최대) |

기록은 최대 절반까지만 반영합니다. 처음 고른 취향이 언제나 절반 이상 남습니다.

### 예시: 식당 8곳을 저장한 사용자

처음 순위는 맛·가성비·분위기입니다. 전체 평균은 맛 4.3, 가성비 4.0, 분위기 3.9, 조용함 3.8로 가정합니다.

| 기준 | 저장한 곳 평균 | 환산 | 시작 | 바뀐 내 별점 | 중요도 |
|---|---|---|---|---|---|
| 맛 | 4.7 | 4.14 | 5.0 | 4.62 | 50 → 42 |
| 가성비 | 4.0 | 3.00 | 4.2 | 3.67 | 30 → 18 |
| 분위기 | 4.6 | 4.27 | 3.8 | 4.01 | 20 → 26 |
| 조용함 | 4.5 | 4.17 | 3.0 | 3.52 | 0 → 14 |

저장한 곳들이 가성비는 평범하고 분위기·조용함은 뛰어났기 때문에 취향이 그쪽으로 이동합니다. 처음에 고르지 않은 조용함도 취향에 들어옵니다.

## 4. 식당 취향 %

식당이 내 별점에 못 미친 만큼만 감점합니다. 더 좋은 것은 감점하지 않습니다. 기준마다 내 합격선이 있고, 넘으면 만점, 못 넘으면 모자란 만큼 깎는 방식입니다.

```text
식당 % = Σ 중요도_i × (1 − max(0, 내 별점_i − 식당 환산_i) / (내 별점_i − 1))
```

- 중요도가 있는 기준만 계산합니다.
- 별점이 없는 기준의 중요도 합이 20% 이상이면 "평가가 부족해요"로 표시합니다. 20% 미만이면 별점이 있는 기준만으로 계산합니다.

예시 (처음 상태, 맛·양·분위기 50·30·20, 전체 평균 4.3·4.0·3.9):

| 식당 (맛·양·분위기) | 이전 공식 | 새 공식 |
|---|---|---|
| 5·5·5 | 100% | 100% |
| 4.8·4.0·3.9 | 85% | 76% |
| 4·4·4 | 75% | 57% |
| 4·3·2 | 58% | 40% |

## 5. 친구 취향 %

두 사람의 별점 묶음을 기준별로 비교합니다. 둘 다 중요하게 여기는 기준일수록 크게 반영하고(두 사람 중요도의 평균), 별점이 2점 이상 차이 나면 그 기준은 완전히 다르다고 봅니다.

```text
친구 % = 100 × (1 − Σ 평균 중요도_i × min(1, |내 별점_i − 친구 별점_i| / 2))
```

| 상황 | 이전 공식 | 새 공식 |
|---|---|---|
| 맛·가성비·분위기 / 맛·분위기·가성비 (처음 상태) | 90% | 90% |
| 맛·가성비·분위기 / 분위기·맛·조용함 (처음 상태) | 50% | 50% |
| 맛·가성비·분위기 / 사진·조용함·주차 (처음 상태) | 0% | 24% |
| 위 두 번째 친구와, 내가 8곳을 저장해 분위기·조용함 쪽으로 이동한 뒤 | 50% | 68% |

추천 정보 활용에 동의한 사용자만 다른 사람의 추천 목록에 나옵니다.

## 6. 주의할 점

- 이 %는 식당을 좋아할 확률이나 친구와 같은 음식을 좋아할 확률이 아닙니다. 내 기준을 얼마나 채우는지, 기준이 얼마나 닮았는지를 보여주는 점수입니다.
- 좋아하는 음식 종류와 식사 상황은 아직 점수에 넣지 않습니다.
- 최근 기록에 더 큰 비중을 주는 규칙은 없습니다.
- 반영 세기(10과 1/2), 환산 폭, 친구 비교의 2점 기준은 조정용 값입니다. 운영 데이터의 별점 분포를 보고 맞춥니다.
- 시드 데이터는 전체 평균을 왜곡합니다. 운영 DB의 QA 시드는 2026년 10월 11일 제거했고, 다시 넣지 않습니다.

## 개발 구현 기준

| 위치 | 역할 |
|---|---|
| `private.criterion_averages()` | 기준별 전체 공개 평균 g (`place_rating_stats` 합계) |
| `public.taste_star(r, g)` | 환산 별점 |
| `private.taste_stars(user)` | 기준별 내 별점, 중요도, 증거 수 |
| `public.get_my_taste()` | 앱용 내 취향: `priorities`, `stars`, `weights`, `averages`, `evidence` (소수 4자리) |
| `public.taste_place_match(taste, averages)` | 식당 % (SQL). AI 검색(`agent_search_places`) 정렬에 사용 |
| `private.taste_match(a, b)` | 친구 %. `get_taste_matches`, `search_profiles`가 사용 |
| `lib/model/taste_profile.dart` | `TasteProfile.match`(식당 %, Dart), `relativeStar`, 전역 `myTaste` |
| `AppController._loadTaste` | 시작할 때, 그리고 `markDataChanged()`(저장·게시·삭제 등)마다 `get_my_taste`를 다시 받음 |
| `profile_map_tab.dart` 취향 카드 | 내 중요도 상위 4개와 "기록 N곳을 반영한 취향이에요" 표시 |

- 식당 % 공식은 SQL과 Dart 두 곳에 있습니다. 같은 골든 숫자(100·76·57·40%, 친구 90·24·94%, 별점 4.7727 등)를 `supabase/tests/follows_taste.sql`과 `test/preferences_test.dart`에서 함께 검증합니다. 한쪽을 고치면 다른 쪽도 고칩니다.
- 내 취향을 받기 전에는 식당 %를 표시하지 않습니다(null). 서버의 처음 고른 순위와 기기의 순위가 다르면 갱신될 때까지 표시하지 않습니다.
- 계산은 서버에서 매번 합니다. 추천 대상 사용자가 많아져 `get_taste_matches`가 느려지면 `taste_profiles`에 별점을 저장해 두는 방식으로 바꿉니다.
